# ПОС — преподавательская оценка студентов

Консольное приложение для ведения рубрикатора и оценок по одному курсу. Реализовано на Python 3.10+ без внешних библиотек.

## Запуск

Из корня проекта:

```bash
python3 -m pos
```

По умолчанию данные хранятся в `data/pos.json`. Другой путь можно передать через `--data`:

```bash
python3 -m pos --data my_grades.json
```

Режим демонстрации создаёт двух студентов, два критерия, выставляет оценки, рассчитывает итог и экспортирует CSV. Основную базу он не затрагивает:

```bash
python3 -m pos --demo --export demo_result.csv
```

В деморежиме тоже можно указать `--policy provisional`. В примере Борис получит `6.00/10` по одному оценённому критерию вместо `3.60/10` по полному рубрикатору.

Запуск тестов:

```bash
python3 -m unittest discover -s tests -v
```

Если требуется установить пакет как команду (необязательно): `python3 -m pip install -e .`, затем `pos`.

## Возможности и бизнес-правила

- Добавление, просмотр и удаление студентов.
- Добавление, просмотр и удаление критериев с `max_score > 0` и `weight > 0`.
- Выставление, просмотр, исправление (повторная установка) и отмена оценок.
- Расчёт результата по весам, экспорт итогов в CSV (UTF-8 с BOM, совместим с Excel).
- Оценка допустима только для существующих студента и критерия и должна попадать в диапазон `0 ≤ score ≤ max_score`. Не допускаются `NaN`, бесконечности и пустые имена.
- Удаление студента удаляет и его оценки; критерий с выставленными оценками удалить нельзя, сначала нужно отменить оценки.

Итог выводится по шкале от 0 до 10:

`10 × Σ(weight_i × score_i / max_score_i) / Σ(weight_i)`

По умолчанию отсутствующие оценки дают нулевой вклад, но **их веса остаются в знаменателе**. Например, критерий «Практика» (максимум 20, вес 0.6) с баллом 18 и «Защита» (максимум 10, вес 0.4) с баллом 8 дают `8.60 / 10`.

Можно запустить `python3 -m pos --policy provisional`. В таком режиме знаменатель содержит только веса оценённых критериев. Это **промежуточный**, а не окончательный результат. Результат округляется до двух знаков после запятой по правилу ROUND_HALF_UP. При отсутствии критериев/оценок он равен нулю.

## DDD: карта предметной области

**Ubiquitous Language:** *студент* (`Student`), *критерий* (`Criterion`), *оценка* (`Evaluation`), *рубрикатор* (набор `Criterion`), *итог* (`GradeSummary`). Имена одинаковы в модели, сценариях и документации.

- **Entity:** `Student` и `Criterion` идентифицируются постоянным ID; `Evaluation` — парой `(student_id, criterion_id)`, поэтому повторное выставление изменяет существующую оценку, а не создаёт дубль.
- **Value Object:** `Score` — неизменяемое значение, проверяющее неотрицательность. В отличие от студента, у балла нет собственного ID; значения `Score(5)` и `Score(5)` эквивалентны.
- **Aggregate Root:** `AssessmentBook` — граница согласованности одного курса. Снаружи нельзя напрямую изменять внутренние словари. Через его методы проверяются существование студента/критерия и пределы баллов. При загрузке из JSON данные проходят те же методы и проверки.
- **Repository Port:** `AssessmentRepository` (`pos/domain/repositories.py`); реализации `JsonAssessmentRepository` и `InMemoryAssessmentRepository` находятся за пределами домена.
- **Domain Service:** `WeightedTotalCalculator` считает итог на основе текущего рубрикатора и оценок — итог нигде не хранится как независимое редактируемое поле.

## Архитектура: Ports & Adapters

```text
CLI → Application → Domain
JSON и память → AssessmentRepository (Domain)
CSV → GradeSummary (Domain), контракт ReportWriter (Application)
bootstrap.py → сборка зависимостей всех слоёв
```

Общее правило зависимостей: **внешние слои импортируют внутренние, но не наоборот**. `domain` не импортирует консоль, JSON, CSV и `application`. `application` зависит от домена и контрактов; адаптеры реализуют контракты; зависимости передаются в конструктор `PosFacade` через `Container` (`bootstrap.py`). Контейнер хранит фабрики и создаёт singleton-экземпляры по запросу. Для замены файла хранилища или политики подсчёта не требуется изменять доменную модель.

## Паттерны GoF

| Группа | Паттерн | Место | Зачем |
|---|---|---|---|
| Порождающий | **Factory Method** (фабричный метод) | `EvaluationFactory`, `NewEvaluationFactory`, `RestoredEvaluationFactory` | Общие проверки диапазона выполняются до создания `Evaluation`. Фабричный метод выбирает источник даты: текущее время при вводе или сохранённое время при загрузке. |
| Структурный | **Facade** | `PosFacade` | Консоль не управляет самостоятельно репозиторием, расчётом и экспортом; работает через единый набор сценариев. |
| Поведенческий | **Strategy** | `MissingAsZero` / `AssessedOnly` | Меняется политика учёта ещё не оценённых критериев без изменения расчётчика и UI. |

## Структура

```text
pos/
  domain/
    model.py             # Сущности, VO, агрегат, фабрика, инварианты
    repositories.py      # Порт репозитория
    services.py          # Итог и стратегии
  application/
    facade.py            # Сценарии приложения
    ports.py             # Порт экспорта
  adapters/
    json_repository.py   # JSON-хранилище
    memory_repository.py # Память: тесты и demo
    csv_report.py        # Экспорт
  bootstrap.py           # DI-контейнер
  cli.py                 # Консольный адаптер
  __main__.py            # python -m pos
tests/                   # unittest
```

## Принятые ограничения

Модуль рассчитан на один курс и один консольный процесс с локальным JSON-хранилищем. Два процесса могут перезаписать изменения друг друга. Чтобы заменить критерий, нужно отменить выставленные по нему оценки, удалить критерий и добавить новый.

## Использование ИИ

ИИ помог обсудить архитектуру и подготовить первый вариант кода, тестов и документации. При проверке ИИ помог обработать `--policy` в деморежиме и защитить файл оценок от перезаписи при экспорте.
